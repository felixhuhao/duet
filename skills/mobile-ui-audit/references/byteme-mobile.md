# Byteme Mobile routing

Read this reference only when the target repository is Byteme Mobile.

## Authority

Locate the repository root and read its current `AGENTS.md` completely. Follow the task routing in that file rather than relying on
paths remembered by this skill. For visual work, locate and read the current Mobile visual/page-shell rules, the named Goal/Ticket,
and the repository's validation and local toolchain instructions when relevant.

Repository rules decide canonical planning location, owner worktree, base pickup, Flutter/OpenHarmony wrappers, branch model, test
frequency, merge/push authorization, and required Device evidence. This reference does not override them.

## Scope reminders

- Preserve the repository's current iOS, Android, and HarmonyOS product scope; emulator residency is not product scope.
- Desktop is a separate product and is not restored or changed by a Mobile UI task.
- Keep UI work visual. API, Cubit/repository behavior, auth, payment/privacy gates, analytics, release configuration, and route
  outcomes need separate authority.
- Web and mini-program may provide information hierarchy or interaction evidence, but do not override native Mobile structure.
- Public, authenticated, money-adjacent, and AI/non-human disclosures remain governed by current repository product rules.
